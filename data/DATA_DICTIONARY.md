# Data dictionary — planned dataset

Status: schema specification; the synthetic evaluation fixtures under `data/evaluation/` now exist (see the last section). No catalogue import file or PDF fixtures yet. Authoritative bounds are in ../docs/handoff/DATA_API_CONTRACT.md.

| Entity / field | Type | Meaning |
|---|---|---|
| import.schema_version | integer | Version 1 of prepared catalogue contract |
| jobs | array | Prepared synthetic or permitted listings |
| source / source_job_id | strings | Provenance and stable provider identity |
| title / company_name | strings | Vacancy and actual employer, not publisher |
| country_code / location | strings | Job location; SG for Singapore |
| description | string | Source text supporting extraction |
| job_type | enum | INTERNSHIP / OTHER / UNKNOWN |
| employment_time | enum | FULL_TIME / PART_TIME / UNKNOWN |
| work_arrangement | enum | ON_SITE / HYBRID / REMOTE / UNKNOWN |
| apply_url / source_url | HTTPS URL | Original application and provenance pages |
| posted_at / last_verified_at | nullable timestamp | Source posting date / explicit availability check |
| eligibility_notes | array of text/source_quote | Conditions for student checking, not ranking |
| requirements | array | Required or preferred technical requirements |
| requirement_text / source_quote | strings | Matching text and supporting original wording |
| alternatives | string array | OR alternatives, scored as one logical requirement |
| evidence_skills | string array | Acceptable explicitly named skill claims |
| is_active | boolean | Explicit catalogue availability flag |
| evaluation.profile_id / job_id | strings | Synthetic fixture identities |
| evaluation.relevance | integer 0–2 | Independently judged irrelevant / partial / relevant |
| evaluation.split | enum | development / held_out |
| evaluation.rationale | string | Human label explanation, not model-generated truth |

Unknown fields remain unknown, not fabricated. Derived hashes, import timestamps, IDs and vectors are generated by importer, not invented by dataset authors. Add actual record counts/checksums once fixtures exist.

In these files `evaluation.job_id` is the job's `source_job_id`. **`evaluation.relevance` values are currently AI-drafted, not
independently human-judged** (drafted from `data/evaluation/LABELLING_CRITERIA.md` before any model output existed);
human review is pending, so this file's "independently judged" wording is not yet true for them. Jobs that need a real
`job_id` UUID, hashes, timestamps or vectors get those from the importer; fixtures do not invent them.
