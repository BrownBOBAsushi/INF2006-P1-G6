# Deployment runner preparation — 2026-09-27

This record began as local preparation evidence: at that stage the runner had not been invoked with `--apply`. A later user-reported trial invoked it twice against the existing healthy stack; both runs completed the SSM catalogue dry-run as no-ops because the expected rows and embeddings were already current. These runs validate only the existing-stack path. A fresh-stack create through this runner remains untested. The user later reported tearing down the temporary foundation resources; current AWS state was not independently verified by Codex.

`src/infra/scripts/deploy-foundation.py` is a standard-library Python entry point. It validates the saved archive SHA-256, archive/manifest agreement, every source file digest and mode, the exact archived CloudFormation template, source identity, image digest shape, repository identity, and the public Google client-ID hash from build provenance. The normal artifact directory and nonsecret defaults are in `src/infra/deploy-foundation.json`; future builds require an explicit `--artifacts` path. No secret values are read or copied locally.

Without `--apply`, it is designed to perform only AWS read operations: caller identity, immutable ECR digest existence, metadata-only `describe-secret` for the five named secrets, current AL2023 AMI, exact CloudWatch log group state, and a fail-closed foundation stack lookup. It rejects secrets scheduled for deletion and never calls `GetSecretValue`. It then reports the planned operation. Applying to a missing stack uses `create-stack --disable-rollback`; it does not delete failed resources. An existing stack is compared against the selected image/source/configuration and is never updated or replaced. Its original AMI parameter remains fixed during resume if the public latest-AMI pointer has advanced. Before returning success for a healthy existing endpoint, SSM runs the fixture importer in dry-run mode and verifies all expected rows and embeddings are current. It imports missing or changed fixture data only when the API service is stopped; if the API is running and the dry-run detects changes, it stops without writing. Incomplete activation resumes DNS/HTTPS. SSM Agent readiness and command execution are bounded and stop on permission errors; remote command output is not copied into local logs.

`--apply` also runs the synthetic catalogue dry run and idempotent apply for a newly created foundation, uses the EC2 instance's current public IPv4 for DuckDNS, waits for public DNS, avoids repeated HTTPS certificate issuance when readiness is already healthy, and checks public `/health/ready`. The result does not establish Google browser sign-in or the full user journey. No teardown command exists. A failure can leave billable resources; diagnose CloudFormation events and secure instance command output before deciding on any cleanup.

The operator's AWS principal permissions for `ssm:SendCommand` and `ssm:GetCommandInvocation` cannot be proven from a pre-create read-only check because there is no target instance yet. The EC2 instance profile separately enables the SSM Agent. The runner calls out the pre-create limitation and stops on a denied SSM operation; if that happens after creation, the retained stack and resources may continue to incur charges until a human reviews them.

Verification commands and results are recorded in the task response. No live AWS, Docker, or internet readiness test was performed by this preparation.
