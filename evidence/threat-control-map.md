# Threat-control map

**Updated:** 2026-10-03. Each row names a threat, the implemented control (with its source location) and the
evidence that the control was exercised. Provenance: **[Captured]** read-only cloud output,
**[Local run]** automated tests on 2026-10-03 (`evidence/local-tests-2026-10-03.md`), **[Observed]** browser
observation, **[Operator-reported]**. "Not tested" is stated where it applies.

| # | Threat | Implemented control | Evidence |
|---|---|---|---|
| T1 | **Unauthenticated access to résumé/profile data** | Every `/api` data route requires a database-backed session resolved from an HttpOnly cookie (`src/backend/app/auth/`) | [Captured] `cloud-capture-2026-10-03/09-public-probes.txt`: `GET /api/me`, `/api/resume`, `/api/matches`, `POST /api/resume/prepare` without cookie → 401 `AUTH_REQUIRED`. [Captured] Logs Insights shows 401s in production traffic (`08-logs-insights.txt`) |
| T2 | **Cross-site request forgery** on state-changing routes | Allowed-Origin check plus session-bound CSRF token header on every POST/PUT/PATCH/DELETE; cookie `SameSite=Lax` (`src/backend/app/auth/router.py`) | [Captured] cross-site or missing Origin on `POST /api/auth/logout` → 403 `CSRF_INVALID` (`09-public-probes.txt`). [Local run] `test_google_exchange_rejects_wrong_csrf`, `test_google_exchange_rejects_bad_origin`, `test_logout_requires_csrf_for_active_session`, `test_patch_me_requires_csrf…`, `test_prepare_requires_csrf…`, `test_delete_resume_rejects_bad_csrf` (133 backend tests passed). [Operator-reported] missing/invalid CSRF with a live session → 403, session retained |
| T3 | **Forged or replayed Google login** | Google ID-token signature, issuer, audience and expiry verified server-side; one-time nonce from `/api/auth/bootstrap` (`src/backend/app/auth/google_verify.py`) | [Local run] `test_bootstrap_issues_nonce_and_cookie`, `tests/backend/test_google_verify_diagnostics.py`. [Operator-reported] real Google sign-in on the deployed stack |
| T4 | **Session theft via script or plain HTTP** | Session cookie `HttpOnly`, `Secure` (non-dev), `SameSite=Lax`, `Path=/`; HTTPS on every hop: browser → API Gateway, API Gateway → ALB (name-verified certificate), ALB → targets | [Captured] `02-ingress.txt` (HTTPS listener, TLS 1.3 policy, `ServerNameToVerify`, HTTPS target group). [Operator-reported] cookie attributes in browser. Limitation: ALB does not validate the target certificate; no HSTS header |
| T5 | **Cross-account data access (IDOR)** | User identity is taken only from the session; no route accepts a user ID; queries filter by the session's user; task completion fenced by owner and revision | [Local run] `test_save_replay_noop_revision_and_operation_ownership`, `test_completion_rejects_wrong_owner_and_stale_revision`. [Operator-reported 2026-09-27] second Google account saw an empty profile. Not tested: direct authenticated API calls across two live accounts |
| T6 | **Malicious or oversized PDF (resource exhaustion, parser exploits)** | Nginx 6 MiB body cap; API 6 MiB multipart / 256 KiB JSON limits; 5 MiB PDF and 10-page limits; encrypted/scanned/not-a-PDF rejected; parsing in a restricted child process with a 60 s deadline; one processing slot per worker; asynchronous queue absorbs bursts | [Observed 2026-10-03] 6,291,457-byte request → 413; 5,242,881-byte PDF → 413 `FILE_TOO_LARGE`; no-file request → 415 `PDF_REQUIRED` (`cloud-acceptance-2026-10-03.md`); [Captured] 413/415 visible in Logs Insights. [Local run] `test_eleven_pages_is_rejected_by_the_page_limit`, PDF edge fixtures |
| T7 | **Personal data leaking into storage, embeddings or logs** | Presidio + app rules replace names, emails, phones, SG addresses, NRIC/FIN IDs and URLs before review; only student-approved text is embedded; PDF held in S3 for at most 1 day and deleted after extraction; Nginx log format omits query strings, cookies and user agents; processing logs counts only | [Local run] `test_no_fictional_pii_survives_prepare…`, `test_each_pii_type_is_replaced_in_plain_text`, `test_logs_contain_counts_only_never_the_original_text`. [Captured] bucket lifecycle 1 day, object count 0 (`05-data-stores.txt`); sanitised `log_format` (`src/infra/nginx/web-private-https.conf`). Limitation: [Observed] "Cloud Computing" was misclassified as a person (over-redaction) |
| T8 | **Direct network access to app, worker or database** | Only `HttpApi` is Internet-facing; ALB is internal; no instance has a public IP; app port 8443 accepts only the ALB security group; worker has no inbound rules; PostgreSQL 5432 accepts only app and worker security groups; RDS not publicly accessible; admin access via Session Manager (no SSH) | [Captured] `03-compute.txt` (`HasPublicIp: false`, IMDSv2 required), `04-security-groups.txt`, `05-data-stores.txt` (`PubliclyAccessible: false`) |
| T9 | **Secret disclosure** | Secrets in AWS Secrets Manager, fetched at boot into root-only 0600 env files; never in images, CloudFormation parameters, repository or logs; `.env` git-ignored; `.env.example` placeholders only | [Captured] `06-secrets-and-logs.txt` (secret names/metadata only; values never retrieved). Source: `src/infra/scripts/write-private-app-compose-env.sh`, `bootstrap-private-worker.sh` |
| T10 | **Excess privilege of a compromised component** | Learner Lab forbids custom IAM roles, so instances share `LabRole`. Compensating controls: network isolation (T8); separate restricted PostgreSQL roles `app_migrator` / `app_runtime` with no superuser/createdb/createrole/bypassrls and `CREATE` revoked from `PUBLIC` (`src/infra/scripts/configure-app-roles.sql`) | [Captured] `03-compute.txt` (`LabInstanceProfile`). Limitation: IAM least privilege is **not** achieved at the role level |
| T11 | **Data at rest exposure** | RDS storage encryption; S3 SSE-S3 with public access blocked and TLS-only bucket policy; SQS SSE | [Captured] `05-data-stores.txt` |
| T12 | **Lost or duplicated updates** (double submit, retries, two tabs) | Revision-checked saves (409 on stale revision), idempotency keys with payload hash, transactional outbox, fenced worker leases, DLQ after 5 receives | [Local run] `test_save_is_idempotent_and_rejects_reuse_with_changed_payload`, `test_delete_resume_rejects_revision_conflict`, `test_locked_revision_refreshes_after_concurrent_commit`, `test_two_database_sessions_cannot_claim_the_same_live_task`. [Observed] offline save retried automatically with one revision increment |
| T13 | **Database loss** | RDS automated backups (1-day retention, point-in-time restore) | [Captured] `05-data-stores.txt` (`BackupRetentionPeriod: 1`, `LatestRestorableTime`). Not tested: restore |

The brief's required security test (Section 5.2) is recorded in [test-security.md](test-security.md), which tests
